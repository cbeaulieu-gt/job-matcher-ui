## CI gate vocabulary (referenced by every issue's acceptance criteria)

Every decomposed issue's acceptance criteria must end with the **full CI gate green** (mirror CI, not
a subset), per FND §4.8 last bullet. The named gates for this repo are:

- `ruff check .` — lint.
- `pytest` against the **Postgres test DB** (`DATABASE_URL` → a DB whose name contains `test`;
  `conftest.py` refuses non-test DBs unless `ALLOW_NON_TEST_DB=1`). Per CLAUDE.md, test isolation is
  **scoped DELETE by a test-specific `source_id` prefix — never `TRUNCATE`**.
- `djlint templates/ --lint` — template lint (only when an issue touches `templates/`; Cycle 0/1
  rarely do, Cycle 3 apply-flow UI does).
- Any `black --check` / `mypy` the workflow runs (state expected test count at implementation time).

**Refactor discipline** (applies to the db/ split, the dedup rewrite, and the feed-query rewrite):
*baseline-first* — capture the current passing test set before touching code; name the specific tests
that must stay green; add the new behavior's tests in the same PR (CLAUDE.md § Testing + Software
Standards TDD). Behavior-preserving moves (db/ split) get a "no behavior change" assertion: the
re-export surface keeps every existing `import db` / `from db import …` caller working (FND §3.2).

# Cycle 0 — Foundation (milestone)

## Milestone definition

- **Title:** `Cycle 0 — Foundation`
- **Description:** Schema + migration foundation for job-matcher 2.0: split `db.py` into a `db/`
  package, add the new 2.0 tables (profile, skills, roles, job_preferences, matches + listing
  lifecycle/applied_resume_id columns) with correct types (ADR-003/004/005/006), and run the one-time
  atomic, idempotent flat-file→DB migration gated by a `schema_version` sentinel (FND §3.3).

## Ordered decomposed issues

Sequenced by FK dependency: package split → version sentinel → parent tables → join table →
listing columns → atomic seed/backfill → tests.

### C0-1 · Split `db.py` into a `db/` package by entity (behavior-preserving)

- **Goal.** Convert the monolithic `db.py` into a `db/` package with a `db/__init__.py` that
  re-exports every existing public symbol, so all current `import db` / `from db import …` callers keep
  working with zero churn. No new tables yet — this is a pure structural move.
- **Acceptance criteria.**
  - [ ] `db/__init__.py` re-exports all symbols the current `db.py` exposes; `grep` shows no caller in
        `web/`, `ingest.py`, `services/`, `tests/` was edited to change its `db` import.
  - [ ] Entity modules exist as the seams for later work (`db/listings.py`, `db/ingest_runs.py`,
        `db/geocache.py` at minimum; `db/profile.py`, `db/roles.py`, `db/matches.py`,
        `db/job_preferences.py`, `db/skills.py` may be created empty/stub for C0-3/C0-4 to fill).
  - [ ] A thin row→dict mapping helper is shared; legacy TEXT-JSON `_deserialise_row` is **not** applied
        to (future) JSONB tables (FND §3.2 — psycopg2 returns JSONB as Python objects already).
  - [ ] Baseline-first: the full pre-split `pytest` set passes unchanged (name it in the PR); no test
        assertions changed except import paths if any module moved.
  - [ ] `ruff check .` + `pytest` (test DB) green.
- **Depends on.** none (first issue).
- **Citations.** ADR-002 (db/ split, no ORM); FND §3.2 (`db/__init__.py` re-export contract,
  per-entity mappers); live anchor `db.py` monolith (`db.py:393-441`, `:700`).

### C0-2 · Add `schema_version` sentinel table + migration guard scaffold

- **Goal.** Create the `schema_version (version INT PK, applied_at TIMESTAMPTZ)` table in `init_db()`
  and the read/guard helper the atomic seed (C0-5) gates on, without yet running any seed.
- **Acceptance criteria.**
  - [ ] `init_db()` creates `schema_version` idempotently (`CREATE TABLE IF NOT EXISTS`).
  - [ ] A helper returns the current schema version (absent → 0) so callers can gate `if version < 1`.
  - [ ] Re-running `init_db()` is a no-op against an already-versioned DB.
  - [ ] `ruff check .` + `pytest` (test DB) green.
- **Depends on.** C0-1.
- **Citations.** FND §3.2 (`schema_version` row in new-tables table), §3.3 (guard is `schema_version`,
  not "profile row exists"); ADR-012 (hand-rolled idempotent migration pattern, `db.py:393-441`).

### C0-3 · Create parent tables: `profile`, `skills`, `roles`, `job_preferences` (idempotent DDL, correct types)

- **Goal.** Add the four parent tables to `init_db()` with the normative shapes and ADR-mandated types
  (singletons via `CHECK (id = 1)`; serial-int PKs + `slug TEXT UNIQUE`; JSONB for the listed array/
  object columns; TIMESTAMPTZ for timestamps).
- **Acceptance criteria.**
  - [ ] `profile` singleton (`CHECK (id = 1)`); JSONB columns for
        `education/anti_preferences/scoring_notes/defaults/residency/base_salary` (FND §3.2, 2.1).
  - [ ] `skills`: `id SERIAL PK`, `slug TEXT UNIQUE`, `name`, `years INT` — `id` is the FK target, slug
        never an FK (ADR-006; FND §2.2).
  - [ ] `roles`: `id SERIAL PK`, `slug UNIQUE`, JSONB for
        `prefilter/scoring_notes/anti_preferences/applicable_skills/overrides`, plus
        `active BOOL`, `archived BOOL`, `updated_at TIMESTAMPTZ` (FND §2.3, §3.2).
  - [ ] `job_preferences` singleton (`CHECK (id = 1)`); JSONB for locations/arrays; money as `NUMERIC`
        with currency+period where applicable (ADR-003; FND §2.4).
  - [ ] All four created **before** `matches` in `init_db()` ordering (FK order — FND §3.2).
  - [ ] JSONB round-trips (write dict → read back equal Python object) covered by a test.
  - [ ] `ruff check .` + `pytest` (test DB) green.
- **Depends on.** C0-1, C0-2.
- **Citations.** ADR-003 (NUMERIC money), ADR-004 (TIMESTAMPTZ), ADR-005 (JSONB, new tables only —
  scope note), ADR-006 (serial-int PK + slug); FND §2.1–2.4, §3.2.

### C0-4 · Create `matches` join table + `listings` 2.0 columns

- **Goal.** Add the `matches` join (PK `(listing_id, role_id)`, FKs with the correct cascade) and the
  two new nullable `listings` columns (`lifecycle TEXT NULL`, `applied_resume_id INTEGER NULL`). The
  `lifecycle` column is added **nullable with NO default** here; it is backfilled + `SET NOT NULL`
  inside the C0-5 transaction (do not stamp a DDL default — FND §3.3).
- **Acceptance criteria.**
  - [ ] `matches` PK `(listing_id, role_id)`; FK `listing_id → listings.id ON DELETE CASCADE`,
        FK `role_id → roles.id`; JSONB `matched_skills/missing_skills/concerns/overridden_via`;
        `score NUMERIC`, `tokens_input/output INT`, `model_used TEXT`, `verdict TEXT`,
        `scored_at TIMESTAMPTZ`; indexes on `role_id` and `listing_id` (FND §2.5, §3.2).
  - [ ] `listings` gains `lifecycle TEXT NULL` (**no** `DEFAULT 'scored'`) and
        `applied_resume_id INTEGER NULL` via the existing `ADD COLUMN IF NOT EXISTS` loop (`db.py:431`).
  - [ ] `ingest_runs` gains `matches_written INT`, `roles_processed INT`; `finish_ingest_run()`
        accepts/reports them (FND §3.2; live anchor `db.py:539`).
  - [ ] `init_db()` succeeds against a **completely empty** DB (FK parent-before-child order holds) —
        integration test asserts this (FND §3.2 / §3.4).
  - [ ] `ruff check .` + `pytest` (test DB) green.
- **Depends on.** C0-3 (FKs target roles; parents must exist first).
- **Citations.** FND §2.5 (Match shape, `lifecycle` naming note), §3.2 (table-creation order,
  `ingest_runs` accounting, nullable lifecycle), §3.3 (why nullable-no-default); ADR-006 (FK targets).

### C0-5 · One-time atomic, idempotent flat-file→DB migration + seed (`schema_version` gated)

- **Goal.** Implement the §3.3 migration inside `init_db()`: gated by `schema_version < 1`, run the seed
  in **one explicit transaction** on a checked-out connection (`autocommit=False` for the block, restored
  in `finally`), seeding Profile + JobPreferences + one Role from the flat files, backfilling `matches`
  for `seen=1` listings, setting `lifecycle` for all rows, `SET NOT NULL`, asserting consistency, and
  inserting the version row last — all-or-nothing.
- **Acceptance criteria.**
  - [ ] Migration seeds Profile (skills `description→name` + slug + serial id, drop `active`;
        education/anti_preferences/scoring_notes → baselines; seniority/preferred_industries → defaults;
        `location.center → current_location.label`), JobPreferences (radius/max_days_old;
        `salary_min → salary_mode='floor'+floor_amount`; contract-type mapping below), and one seeded
        Role (`applicable_skills = ALL skill ids`; empty additions/overrides; `active=true, archived=false`).
  - [ ] **Contract-type mapping table applied exactly** (FND §3.3): `require_contract_time=full_time →
        job_types+=[full_time]`; `part_time → [part_time]`; `require_contract_type=contract →
        [contract]`; `permanent →` (no member); null/absent → no constraint; **any unrecognized value →
        log warning + drop the filter** (never silently over/under-filter).
  - [ ] Backfill: one `matches` row per `seen=1` listing vs the seeded Role (copy score/verdict/skills/
        concerns/model/tokens); `seen=1 → lifecycle='scored'`, `seen=0 → lifecycle='discovered'`; then
        `ALTER COLUMN lifecycle SET NOT NULL` **inside the txn**.
  - [ ] Post-backfill **assertion `COUNT(matches) == COUNT(listings WHERE seen=1)` is INSIDE the txn**,
        before the `schema_version` insert; on mismatch it RAISEs and rolls back (corrupt migration is
        never marked done).
  - [ ] `autocommit` restored to `True` in a `finally` (the pooled connection is recycled by autocommit
        callers — `db.py:310-370`).
  - [ ] Re-running `init_db()` after a successful migration is a no-op (version already 1).
  - [ ] `ruff check .` + `pytest` (test DB) green.
- **Depends on.** C0-4 (matches + lifecycle column must exist), C0-2 (sentinel + guard).
- **Citations.** FND §3.3 (full migration pseudocode, the four "why these specifics" bullets, D13/D21),
  §3.3 contract-type table (O5); ADR-001 (config→Postgres), ADR-012 (hand-rolled); live seam
  `db.py:310-370` (autocommit pool + commit).

### C0-6 · Cycle 0 verification: interrupted-migration + schema/idempotency tests

- **Goal.** Add the dedicated regression tests that guard the migration's hardest invariants
  (interrupted run, idempotency, lifecycle backfill mapping, JSONB round-trip), all under the scoped-
  DELETE test-isolation discipline.
- **Acceptance criteria.**
  - [ ] **Interrupted-migration test:** simulate a kill between seed step 1 and the assertion (no commit)
        → a subsequent `init_db()` **completes** the seed cleanly (no half-migrated lock); the post-commit
        assertion `COUNT(matches)==COUNT(seen=1)` holds (FND §3.4).
  - [ ] `seen=0 → lifecycle='discovered'`, `seen=1 → lifecycle='scored'` asserted on seeded rows.
  - [ ] Contract-type mapping table verified including the unrecognized-value-logs-and-drops case.
  - [ ] `init_db()` against a completely empty DB succeeds and is a no-op on re-run.
  - [ ] JSONB round-trip asserted; `conftest.py` test-DB guard respected; **scoped DELETE by `source_id`
        prefix, no `TRUNCATE`** anywhere added.
  - [ ] `ruff check .` + `pytest` (test DB) green; state the expected test count in the PR.
- **Depends on.** C0-5.
- **Citations.** FND §3.4 (Cycle 0 acceptance criteria — this issue is the test-coverage half);
  CLAUDE.md § Testing / conftest isolation (scoped DELETE, no TRUNCATE).

## Cycle 0 dependency DAG

```
C0-1 (db/ split)
  └─> C0-2 (schema_version sentinel)
        └─> C0-3 (profile, skills, roles, job_preferences)   [parents]
              └─> C0-4 (matches join + listings columns)     [children]
                    └─> C0-5 (atomic seed + backfill)
                          └─> C0-6 (interrupted/idempotency tests)
```

Cycle 0 is essentially **linear by FK dependency** — little safe parallelism (each table layer feeds
the next; the migration needs them all). The only candidate parallel split would be authoring C0-6's
*test scaffolding* alongside C0-5, but the tests assert C0-5's behavior, so keep them sequential for an
autonomous loop. **6 issues.**

### C1-2 · Match-aware dedup primitive: `upsert_listing` + `score_role` (replace boolean `listing_exists`)

- **Goal.** Replace the per-listing boolean short-circuit (`ingest.py:1383-1394`) with the upsert-then-
  check-per-`(listing, role)` primitive: `upsert_listing(...) -> listing_id` (URL cross-source dedup
  retained → `INSERT … ON CONFLICT (source, source_id) DO NOTHING RETURNING id` → **mandatory `SELECT
  id` on the conflict path**), and `score_role(listing_id, role)` writing `matches … ON CONFLICT
  (listing_id, role_id) DO NOTHING`. This is the BLOCKER fix that makes the many-to-many fan-out work.
- **Acceptance criteria.**
  - [ ] `upsert_listing` retains URL cross-source dedup (`listing_exists_by_url`, `db.py:683`) before the
        ON CONFLICT insert.
  - [ ] On the **conflict path** (pre-existing listing), `RETURNING id` is null → the code performs the
        **mandatory `SELECT id WHERE (source, source_id)`** and returns a valid id (N1/D18).
  - [ ] `score_role` inserts a Match with `ON CONFLICT (listing_id, role_id) DO NOTHING` (idempotent —
        a re-run or concurrent write cannot double-insert).
  - [ ] **Dedup-on-conflict test (N1):** `upsert_listing` returns a valid id on the conflict path (not
        null); a re-run does not double-insert Matches.
  - [ ] Baseline-first: existing dedup tests are migrated/renamed, not deleted; the old boolean
        `listing_exists` skip path is removed (or left only for non-role callers if any remain — name them).
  - [ ] `ruff check .` + `pytest` (test DB) green.
- **Depends on.** C1-1 (and C0-5). At the issue level: **blocked-by C0-5**.
- **Citations.** FND §4.1 (upsert pseudocode), D12 (match-aware dedup blocker), D18 (RETURNING-null →
  mandatory SELECT; Match ON CONFLICT); live anchors `ingest.py:1383-1394`, `db.py:683`, `:700`.
